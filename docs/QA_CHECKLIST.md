# AgoraX — Πλήρης Ποιοτικός Έλεγχος (QA Checklist)

Οδηγίες για τον εκτελεστή (άνθρωπο ή AI): δούλεψε αυτόνομα, χωρίς ερωτήσεις,
με ασφαλείς προεπιλογές. Επαλήθευε **εκτελώντας**, όχι μόνο διαβάζοντας.
Διόρθωσε ό,τι είναι χαμηλού ρίσκου με μικρά, καθαρά commits· ό,τι είναι
ριψοκίνδυνο, κατέγραψέ το χωρίς να το αλλάξεις. Στο τέλος: μία αναφορά.

## Περιβάλλον

- Παραγωγή: https://agoraxdemocracy.com — VPS, systemd service `agorax`,
  nginx μπροστά, Node στο :3000, ρυθμίσεις στο `/opt/agorax/.env`.
- Deploy: `git pull` → **πρώτα** εφάρμοσε τυχόν νέα `migrations/*.sql` με
  psql (δεν τρέχουν αυτόματα — η παράλειψη έχει προκαλέσει βλάβη στο
  παρελθόν) → `npm run build` → `systemctl restart agorax`.
- ΠΟΤΕ `npm ci --omit=dev` στο VPS (τα build tools είναι devDependencies).
- Καταστροφικές δοκιμές ΜΟΝΟ στην τοπική βάση dev. Στην παραγωγή: μόνο
  ανάγνωση, εκτός από σαφώς μαρκαρισμένες δοκιμαστικές εγγραφές που
  διαγράφεις μετά.

## Α. Λειτουργικός έλεγχος (E2E σε τοπικό dev server, spot-check παραγωγής read-only)

1. **Πρόταση — διαδρομή διαβούλευσης**: υποβολή → έλεγχος AI → φάση
   τροπολογιών (το τελικό κείμενο AI ξανασυντίθεται ζωντανά όταν ο
   συγγραφέας αποδέχεται/απορρίπτει) → οι αντιπροτάσεις γίνονται
   εναλλακτικές του ψηφοδελτίου → πάγωμα στη λήξη → ψηφοφορία επιλογών →
   καταγραφή νικήτριας επιλογής.
2. **Πρόταση — άμεση ψηφοφορία**: διάρκεια που ορίζει ο συγγραφέας,
   προαιρετικές 2–10 επιλογές, αυτόματη προσθήκη «Καμία αλλαγή»,
   αυτόματη ολοκλήρωση στη λήξη.
3. **Ψηφοφορία ως εμπειρία χρήστη**: το σφραγισμένο ψηφοδέλτιο επιβιώνει
   από κλείσιμο του browser, καταχωρείται αυτόματα στο επόμενο άνοιγμα
   της εφαρμογής, η απόδειξη εμφανίζεται, το πιστοποιητικό κατεβαίνει,
   και η σελίδα /verify δίνει σωστό «Γνήσιο / Δεν βρέθηκε».
4. **Ρυθμίσεις ορατότητας κοινότητας**: όταν μια κοινότητα έχει
   περιεχόμενο «μόνο μέλη», βεβαιώσου ότι ισχύει παντού — ροή, αναζήτηση,
   αναλυτικά, λίστες συνδιασκέψεων, ημερολόγια. Ο αριθμός μελών και ο
   ιδρυτής μένουν πάντα δημόσιοι. Οι ψηφιζόμενες ρυθμίσεις (αυτόνομες
   κοινότητες) εφαρμόζονται με 50%+1.
5. **Συνδιασκέψεις**: κάθε μέλος μπορεί να ξεκινήσει· ο δημιουργός και οι
   διαχειριστές μπορούν να τερματίσουν· η ζωντανή κλήση εμφανίζεται στη
   λωρίδα της κοινότητας μέσα σε ένα λεπτό· η σελίδα /conference δουλεύει
   (lobby → κλήση → έξοδος, καταγραφή συμμετοχής).
6. **Δημοσκοπήσεις**: δημιουργία, απαντήσεις πάνελ, κλείσιμο → παγωμένα
   αποτελέσματα, όριο 5 συμμετοχών για εμφάνιση.
7. **Ειδοποιήσεις**: in-app και push — δημιούργησε ένα γεγονός και δες τη
   διαδρομή ως το καμπανάκι.
8. **Διαγραφή/απόσυρση πρότασης**: διαγραφή μόνο χωρίς συνεισφορές άλλων·
   αλλιώς προσφέρεται απόσυρση· ψηφισμένες ποτέ.
9. **Αρχειοθετημένες**: εκτός ροής και προεπιλεγμένων λιστών, ορατές μόνο
   με το φίλτρο τους.
10. **Αναζήτηση**: προτάσεις + μέλη + κοινότητες, με σεβασμό στην
    ορατότητα και στα ιδιωτικά προσχέδια.
11. **Αναλυτικά (/analytics)**: τα νούμερα να συμφωνούν με απευθείας
    μετρήσεις στη βάση.
12. **i18n**: `npm run check:i18n` καθαρό· επιπλέον grep για κλειδιά `t('`
    που λείπουν από τα locales (τα κλειδιά που λείπουν εμφανίζονται ωμά).
13. **Πλοήγηση & σελίδες**: bottom nav (Αρχική/Κοινότητες/＋/Δημοσκοπήσεις/
    Προφίλ), /walkthrough, /how-it-works, κάρτα καθοδήγησης στη ροή,
    επεξηγηματική γραμμή κάτω από τον stepper.

## Β. Αξιοπιστία

1. Σάρωσε το `journalctl -u agorax` για τις τελευταίες 7 ημέρες — κάθε
   επαναλαμβανόμενο σφάλμα ή προειδοποίηση είτε εξηγείται είτε
   διορθώνεται.
2. Ουρά εργασιών: δοκίμασε τι συμβαίνει όταν το LLM endpoint δεν
   αποκρίνεται σε κάθε στάδιο (έλεγχος, σύνθεση, αναδιατύπωση,
   βελτίωση) — κανένα στάδιο δεν επιτρέπεται να μπλοκάρει τον κύκλο ζωής
   μιας πρότασης· όλα πρέπει να υποβαθμίζονται ομαλά.
3. Αντίγραφα ασφαλείας: επιβεβαίωσε ότι τα ημερήσια pg_dump υπάρχουν και
   είναι πρόσφατα, και **κάνε restore ένα** σε πρόχειρη βάση για να
   αποδείξεις ότι δουλεύουν.
4. Χώρος δίσκου και μνήμη στο VPS: υπάρχει περιθώριο;
5. Σύγκρινε το σχήμα της παραγωγής (information_schema) με το
   shared/schema.ts — καμία απόκλιση. (Το drizzle journal είναι
   παρωχημένο· αγνόησέ το.)
6. Τρέξε τα εργαλεία ελέγχου εξαρτήσεων του npm και σημείωσε ό,τι
   χρειάζεται αναβάθμιση.

## Γ. Καθαριότητα αποθετηρίου

1. Διόρθωσε τα δύο προϋπάρχοντα σφάλματα TypeScript (use-push.ts,
   server/db.ts).
2. Νεκρός κώδικας: legacy amendment-merger.ts, αχρησιμοποίητο
   ActiveCallBanner, stubs στο legacy storage.
3. Tests: το `npm test` αναφέρεται σε vitest που δεν είναι εγκατεστημένο —
   κάνε το να τρέχει και πρόσθεσε integration tests για τα δύο πιο
   κρίσιμα αναλλοίωτα: (α) η επιλογή ψήφου ελέγχεται πάντα απέναντι στο
   σύνολο επιλογών της πρότασης, (β) οι κανόνες ορατότητας περιεχομένου
   κοινότητας.
4. README/CLAUDE.md: αντιστοιχούν στην πραγματικότητα;
5. GitHub Actions: το APK build (tags v*-mobile) περνάει ακόμη;

## Δ. Τι λείπει (backlog)

1. Διάβασε ΟΛΑ τα /opt/agorax/feedback/*.json και κατάγραψε κάθε αίτημα
   που δεν έχει υλοποιηθεί.
2. Συγχώνευσε με κενά που εντοπίζεις ο ίδιος.
3. Υποψήφια προς αξιολόγηση (ΟΧΙ αυτόματη υλοποίηση): προτάσεις με
   αριθμημένες παραγράφους και τροπολογίες ανά παράγραφο· φάκελοι/θέματα
   διαβουλεύσεων· δημιουργία της Γενικής κοινότητας (ο κώδικας αυτόματης
   εγγραφής υπάρχει, η εγγραφή στη βάση όχι)· UI προτιμήσεων
   ειδοποιήσεων· καταγραφή συνδιασκέψεων (LiveKit egress)· ροή σώματος
   έφεσης για την κλήρωση· πλήρης αναζήτηση κειμένου με ελληνικό
   stemming· σενάριο επεξηγηματικού βίντεο.
4. Παράδοσε top-10 με κατάταξη κατά (ζήτηση χρηστών × δημοκρατική αξία ÷
   κόπο).
